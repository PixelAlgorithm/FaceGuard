Rules:
- Sandbox = AWS Workshop Studio event "HID Hackathon GenAI - University"; **region us-east-1 only** (production would pin ap-south-1 Mumbai for DPDP data residency — say so, don't build it). The event IAM role is limited (workshop template: EC2/S3/VPC/RDS), so Rekognition / SES / DynamoDB / KMS / IAM may be denied: every cloud feature needs a degraded path selected by env vars, and the local-first edge must keep working without the cloud. The probe (`cloud/infra/probe_sandbox.sh`) is done; keep `cloud/SANDBOX.md` in line with it. If Rekognition becomes unavailable, report immediately (fallback: `match.rekognition.enabled: false` → local matcher with offline bars).
- Rekognition: consenting team faces only (operator decision), collection deleted at teardown. Design for the stricter Mumbai default quotas (search ~5 TPS, Face Liveness 5 TPS / 15 concurrent). Bangalore ↔ us-east-1 RTT ≈ 200–250 ms: the edge calls `/v1/match` in parallel and time-boxed; a timeout makes that attempt OFFLINE (P7). There is no per-attempt schedule call — the edge evaluates the schedule on the signed bundle you issue (refreshed every 15 min + revocation feed).
- No SMS OTP (TRAI DLT). Email OTP via SES (verify sender/recipients in sandbox) or on-screen/TOTP.
- Never commit credentials; use env vars / IAM roles (never copy session keys onto instances). S3 SSE-KMS with a **1-day** lifecycle for audit frames, DynamoDB TTL on decisions. Bundle signature = HMAC-SHA256 with `SCHEDULE_BUNDLE_HMAC_KEY` (Ed25519 in production; never KMS/ECDSA); signer stamps `issued_at` = now, `expires_at` = now + 12 h, override codes `valid_until` = `expires_at` + `fallback.staff_override.valid_after_expiry_h` (24 h).
- `/v1/sync` follows `docs/API.md` v1.1 exactly (≤ 50 items incl. TOMBSTONE items, `chain_head` + `chain_head_hmac`; response `accepted` / `duplicates` / `rejected` / `flags`). Use the fallback record's `totp_step` to flag cross-kiosk TOTP replay (Y07).
- **Test on your own port, never against the live `:8000` edge or the deployed cloud.** Run the cloud locally on a scratch port; the live edge's `CLOUD_API_URL` may point at the deployment.
- Ask the user before creating anything billable outside the sandbox or anything hard to tear down. Provide a teardown script.
- Use `fastapi-patterns` and `deployment-patterns` skills.
